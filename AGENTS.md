# Repository working instructions

- Before planning or changing this game, list the files in `docs/` and read the documentation relevant to the request. Treat those documents as project context, then check the current code before making implementation claims.
- Put all new plans, design notes, specifications, and markup documents in `docs/`, with descriptive Markdown filenames. Update an existing document there when it already covers the topic.
- Keep links to moved or renamed documents current in `README.md` and in other affected docs.
