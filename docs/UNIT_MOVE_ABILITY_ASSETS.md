# Unit, move, and ability asset authoring

Use this guide when making original art or sound for a Pokémon, a move, or an ability. The game serves source assets from `public/assets/`; `dist/` is generated by the local build and should never be edited as the source of an asset. The [animation guide](ANIMATION_ASSETS.md) has the current frame timings and existing asset inventory; the [audio guide](AUDIO_ASSETS.md) covers sound export and mixing.

## IDs, names, and locations

The **content ID** is the key used by game code, manifests, and saved runs. Keep it stable. Display names and filenames can differ from it. Use lowercase `camelCase` for move IDs, lowercase `kebab-case` for species/form IDs, and the existing display-name style for ability IDs. Use lowercase `kebab-case` in filenames, with the asset's role at the front.

| Kind | Example content ID | Suggested asset name | Registration |
| --- | --- | --- | --- |
| Species | `pikachu` | `units/pikachu/pikachu-idle-32x40.png` | `unitSets` and `units` in the animation manifest |
| Separate form | `charizard-mega-x` | `units/charizard-mega-x/charizard-mega-x-idle-32x40.png` | Its own species and unit-set mapping |
| Move | `thunderShock` | `attacks/attack-thunder-shock-32px.png` | `attacks.thunderShock` in the animation manifest |
| Move sound | `thunderShock` | `moves/move-thunder-shock.wav` | `moves.thunderShock` in the audio manifest |
| Ability | `Water Absorb` | `abilities/ability-water-absorb.wav` | `abilities["Water Absorb"]` in the audio manifest |

Manifest URLs start at `/assets/...`, **without** `/public`. Adding a file does not make the game use it until its manifest entry points to it. Existing content IDs may occur in saves, so renaming an ID needs a save migration; changing a filename or URL does not.

## 1. Make or replace a unit

The battle unit uses seven action clips and one portrait. Its sprite sheet files belong in `public/assets/animations/units/<species-id>/`. Use names such as `<species-id>-idle-32x40.png`, `<species-id>-walk-32x40.png`, `<species-id>-attack-80x88.png`, `<species-id>-shoot-64x64.png`, `<species-id>-charge-32x40.png`, `<species-id>-sleep-32x40.png`, `<species-id>-hurt-56x56.png`, and `<species-id>-normal.png`. These dimensions describe the **example placeholder's frame size**, not a required size for every species. The manifest states each clip's actual size.

| Clip | When it plays | Current placeholder layout |
| --- | --- | --- |
| `idle` | Waiting | 5 frames across × 8 facing rows |
| `walk` | Following a grid path | 7 × 8 |
| `attack` | Melee damaging move | 11 × 8 |
| `shoot` | Ranged damaging move | 12 × 8 |
| `charge` | Status move, buff, debuff, or item action | 10 × 8 |
| `sleep` | Sleep or impaired resting state | 7 × 1; shared for every facing |
| `hurt` | Damage reaction and faint | 2 × 8 |
| `normal` | Portrait in menus and deployment | One standalone image, not a strip |

Export transparent PNG sheets. Within a clip, every frame has the same width and height; frames run left to right and facing rows top to bottom. Sheet width is `frameWidth × frames` and height is `frameHeight × rows`. For example, a 5-frame, 8-row idle clip at 32×40 per frame is **160×320 pixels**. Keep the Pokémon's feet or ground point in the same place across idle, walk, attack, shoot, charge, and hurt, even when those clips use different frame dimensions. Leave room for the animation without clipping at frame edges. Pixel art is displayed with nearest-neighbor filtering on the top-down board.

The supplied placeholder row order is **down, down-right, right, up-right, up, up-left, left, down-left**. Its `facingRows` is `[0, 6, 2, 4]` for the game's logical south, west, east, north order in the top-down view. If your sheets use a different row order, set `facingRows` to the row indices for those four directions. A one-row clip such as `sleep` ignores the facing mapping. The board does not flip a sprite automatically to create missing directions.

Optional ground-shadow sheets go beside their matching clips: `<species-id>-idle-shadow-32x40.png`, `<species-id>-attack-shadow-80x88.png`, and so on. Each must have the **same frame size, columns, and rows** as its clip. The renderer tints these sheets black at low opacity. Missing shadow clips use the first Idle shadow frame for the facing; if the whole set has no shadow sheets, the board still has its simple ground shadow. Flying and swimming use separate ground-projection and ripple overlays.

To assign a new unit set:

1. Copy the `placeholder` object under `unitSets` in [animation-manifest.json](../public/assets/animations/animation-manifest.json) and give the copy a unique key, such as `pikachu`. Keep all seven `clips` keys. Update each clip's `url`, `frameWidth`, `frameHeight`, `frames`, `rows`, `fps`, `loop`, and the `attack`/`shoot`/`charge` `impactFrame` where applicable. An impact frame is zero-based and controls when the effect and damage reaction appear. Set `normal` to your portrait URL.
2. Change `units.pikachu` from `"placeholder"` to `"pikachu"`. That mapping, rather than the folder name alone, selects the set. Multiple species can intentionally share one set.
3. Update `facingRows` for your sheet's direction order. Add `shadows` entries only for sheets you supplied; remove any copied placeholder shadow URL that should not be used.
4. If this is a new playable species, also add its stats, types, ability, mobility, and moves to [species.ts](../src/content/species.ts). Add it to a starter, recruit, or encounter list only where it should appear. A Mega form is a separate species ID and can have its own unit set.

To replace art at an existing URL, overwrite only that source PNG in `public/` and keep its sheet layout. To change dimensions, frame counts, or direction order, update the corresponding manifest fields. A portrait may use a different size from the action frames; it is displayed inside a portrait container with `contain` sizing.

## 2. Make or replace a move

A move has **two layers of animation**: the user's unit clip (`attack` for melee damage, `shoot` for ranged damage, `charge` for Status moves) and a separate effect sheet. `category` and `delivery` in [moves.ts](../src/content/moves.ts) select the unit clip. The attack manifest's `style` controls the effect's placement. Art settings do not change damage, range, targeting, AP, tags, or combat RNG.

Make one transparent **128×32 PNG**, consisting of four 32×32 frames in a single row, in `public/assets/animations/attacks/`. Name it `attack-<move-id-in-kebab-case>-32px.png`. For a move called `thunderShock`, keep the manifest key `thunderShock` and use `attack-thunder-shock-32px.png` as its filename. The current renderer reads the shared `attackFrameCount: 4` and `attackFps: 12`; a longer or differently sized effect needs a renderer/manifest extension, not just a larger file.

Choose one `style` in the animation manifest:

| Style | What the board does |
| --- | --- |
| `melee` | Plays the effect at the impacted tile |
| `projectile` | Moves the sheet from user to selected tile, then plays it at impact |
| `area` | Plays the sheet over affected tiles |
| `self` | Plays the sheet on the user's tile |
| `weather` | Plays a brief cue at several board positions |

For example, adding a named sheet under `attacks` in [animation-manifest.json](../public/assets/animations/animation-manifest.json) makes it take priority over a reusable placeholder:

```json
"thunderShock": {
  "url": "/assets/animations/attacks/attack-thunder-shock-32px.png",
  "style": "projectile"
}
```

For a move still being designed, use one of the six sheets in `public/assets/animations/move-placeholders/`: `placeholderMelee`, `placeholderProjectile`, `placeholderArea`, `placeholderSelf`, `placeholderHazard`, or `placeholderWeather`. A new move chooses one by its definition automatically, or `visualId` can select any existing attack asset ID. A named `attacks` entry matching the move ID wins over `visualId`. Shared placeholder pixels are tinted to the move's type; named art keeps its own colors. See the [placeholder preview](MOVE_PLACEHOLDER_PREVIEW.png).

Put a short sound at `public/assets/audio/moves/move-<move-id-in-kebab-case>.wav` and add a `moves` entry with the **exact move ID** in [audio-manifest.json](../public/assets/audio/audio-manifest.json). A named sound also takes priority over `soundId` in the move definition. Without a named sound, `soundId` may select an existing named move sound or one of the six role keys `melee`, `projectile`, `area`, `self`, `hazard`, and `weather`; otherwise the role is chosen automatically. Keep `visualId` and `soundId` independent so you can replace one asset at a time.

For a brand-new move, add its rules to [moves.ts](../src/content/moves.ts) and then assign its ID to a species' starting moves, level learnset, or `tmMoves` compatibility in `species.ts`. `pokefiles/Moves.csv` is a reference dataset and does not drive the game; keep its game-specific description in sync with the playable definition. A TM-taught move still uses Physical, Special, or Status as its battle category; TM is its acquisition path. To make a TM item, add `teachesMove: '<moveId>'` in [items.ts](../src/content/items.ts), include it in [shop.ts](../src/content/shop.ts) if sold, and give it a Bag icon named `public/assets/ui/icons/item-<item-name-in-kebab-case>.svg`. The current placeholders are `item-tm-swift.svg` and `item-tm-thunderbolt.svg`. TMs are single-use and cannot be held. Its `tags` array may contain several values, such as `['punch', 'contact']`; visual style does not imply a gameplay tag. The current effect resolver supports the effect kinds listed in [types.ts](../src/game/types.ts). A new effect kind needs rule resolution and preview support as well as art.

## 3. Make or replace an ability

Ability rules live in [abilities.ts](../src/content/abilities.ts); a species selects one with its `ability` field. The ability ID is currently a display string such as `Static` or `Water Absorb`. These IDs are also stored on battle units, so keep them stable.

Ability activation currently has **a text callout and a sound**, with no per-ability sprite or icon manifest. For a unique trigger sound, export `public/assets/audio/abilities/ability-<ability-id-in-kebab-case>.wav` and map the exact ability ID under `abilities` in [audio-manifest.json](../public/assets/audio/audio-manifest.json):

```json
"Water Absorb": "/assets/audio/abilities/ability-water-absorb.wav"
```

The battle board plays this sound when the engine emits an ability feedback event. An ability with no audio entry is silent; adding a file alone will not create a trigger. For a new ability, define its supported rule shape in `abilities.ts`, assign it in `species.ts`, and make sure its activation path emits feedback in the game engine. Existing rule shapes include weather speed, damage bonuses, absorption, weather evasion, and contact reaction. If the ability needs a new rule family, extend the rules and feedback path explicitly. Ability artwork, such as a unique icon or effect, would also require a new manifest field and rendering code; placing a PNG in the folder will not display it yet.

## Before using replacement assets

- Check each PNG's transparency, exact frame size, sheet width/height, row order, and stable ground point. Preview all frames and facings, then inspect idle, walking, attacking, and hurt states on the top-down board. Check silhouettes against grass, water, and elevation.
- Check effect art at its actual 32×32 game scale, including the projectile in transit and any area tiles. Keep important pixels inside each frame.
- Check the sound's start/end for clicks and compare its loudness with existing cues. Keep the audio manifest URL and file extension in sync.
- Record the source or creator and usage rights for any asset that will ship. Preserve editable source files outside `dist/`.
- Refresh the local Vite browser after changing assets or manifests. A local `npm run build` checks TypeScript and bundling; visual timing and sound still need an in-game review. The [Battle Lab](BATTLE_LAB.md) lets you control both sides for that review.
